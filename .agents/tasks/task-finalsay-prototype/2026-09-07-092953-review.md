# FinalSay prototype — v2 review (fixes for the 8 v1 concerns)

The second pass verifies the coder's fixes for the eight concerns raised in v1: the three blockers (open role self-assignment at registration, the integrity path being inert on a fresh demo, and self-fulfilling eval metrics) and five lesser issues (leaf_index collision, ungated submit, narrow canonical hash, a dead fixture seam, client-only alerts). Every fix was checked against the code, the test suite (50 pass), both eval splits (exit 0 with honest, non-perfect metrics), and a green frontend build. All eight are genuinely resolved and no regressions were introduced by the fixes.

Watch for: nothing blocking. The two documented deviations (SQLite default in the sandbox, image OCR degrading to 422 with Tesseract absent) are intentional and out of scope. The one residual is that `audience` extraction F1 sits at 0.500 (confirmed) — a pre-existing extraction-quality limit, not a regression, surfaced honestly by the now-truthful harness.

**Verdict**: APPROVED

## High-level view

Registration no longer accepts a role. `UserRegister` dropped the field entirely and `register()` hard-codes `SELF_REGISTER_ROLE = "student"`; privileged accounts exist only through the seed's four demo users. A dedicated test proves a public caller asking for `admin`/`reviewer`/`issuer` is downgraded to student and is then actually 403'd from an admin route — closing the trust-boundary hole against R7.1.

The fresh-demo integrity gap is closed by `provenance.build_all_missing_roots(db)`, called at the tail of `seed()`. It builds a daily root per notice-day, skipping days that already have one, so it is idempotent — verified by `test_seed_is_idempotent` (stable root/proof/anchor counts across two runs) and `test_fresh_seed_verifies_a_notice` (a seeded notice returns `ok=true` with no admin step, and `proof_count == notice_count`).

The eval metrics are now honest. Held-out submissions (`temporal_bucket==1`) use `_naturalistic_text` phrasings that deliberately drop the reverse-engineered keyword cues, so the mock engine must reason from conflicting dates and negation alone. The result is FinalSay temporal F1 ~0.05 and institution F1 ~0.74 — no longer 1.000 — while FinalSay is the only system with a 0.000 false-confirmation rate, routing ambiguous cases to the reviewer queue instead of guessing. The harness docstring and printed report now state this explicitly.

The five lesser fixes all landed: `leaf_index` is now the positional `enumerate` index (so the duplicate-hash `unresolved` submissions no longer collide); `POST /api/ingest/submit` is gated to `require_role("student", "admin")`; `sha256_notice` now folds labelled issuer/date/deadline/audience/action/redacted_text into the canonical form so a single-column edit is tamper-detectable; the dead `fixtures=` seam is gone from `MockComparisonModel` and its docstring corrected to say classification is 100% rule-based; and the alerts page carries an explicit "Prototype stub" notice about its localStorage-only subscriptions.

### Role self-assignment closed at the schema and the endpoint

`UserRegister` no longer carries a `role` field, and `register()` constructs the `User` with `role=SELF_REGISTER_ROLE` (`"student"`). `require_role` is unchanged and still re-reads the role from the DB.

`test_public_register_cannot_self_assign_privileged_role` exercises the full path, not just the persisted column: it registers with each of `admin`/`reviewer`/`issuer` in the body, asserts the persisted role is `student`, then logs in as the downgraded "admin" claimant and confirms `POST /api/ingest/fetch` returns 403.

### Fresh-demo integrity via build_all_missing_roots

`build_all_missing_roots` groups notices by creation day and builds a root only for days without an existing `MerkleRoot` (the skip guard is what makes re-seeding safe); `seed()` calls it after all notices and submissions are ingested. `test_seed_is_idempotent` asserts `merkle_roots`/`merkle_proofs`/`anchor_blocks` counts are identical across two `seed()` runs, and `test_fresh_seed_verifies_a_notice` asserts `proof_count == notice_count` and that a seeded notice verifies `ok=true, tamper=false` with no admin step.

### leaf_index positional fix confirmed end to end

`build_daily_merkle` now iterates `enumerate(zip(notices, proofs))` and stores the loop index, replacing the v1 `leaves.index(notice.sha256)` that returned the first matching position. This matters because the seed generates several `unresolved` submissions from identical ambiguous text that hash identically. The `proof_count == notice_count` assertion confirms each colliding-hash notice still gets its own distinct proof row rather than being collapsed, and every notice verifies.

### Canonical hash now covers every evidence field

`sha256_notice` builds a labelled, newline-joined canonical form over issuer/date/deadline/audience/action/redacted_text, so a targeted edit to any single column now changes the hash; the labelling also prevents a value moving between columns from colliding with another field's value. `build_daily_merkle` and `verify_notice` both pass all six fields, so build and verify recompute over the same canonical form — no asymmetry.

### Eval honesty: naturalistic held-out phrasings

`dataset.generate_submissions` splits phrasing by round: the first two rounds per institution use cue phrasings (so the seeded demo still shows every taxonomy label), and the temporal-holdout round routes through `_naturalistic_text`, which omits the exact keywords the mock rule engine keys on. The superseded case says "originally set for 15 Sep will now take place on 22 Sep" with no "postponed" cue, forcing date-conflict reasoning; the contradictory case pairs conflicting dates with a negation but no postpone cue. Because the superseded rule requires a postpone/reschedule cue, these held-out cases legitimately fall through to `contradictory` or gated `unresolved`, which is why temporal F1 drops to ~0.05.

The two splits, run fresh:

```
temporal     finalsay f1 0.048  false_conf 0.000  unresolved 0.286
institution  finalsay f1 0.739  false_conf 0.000  unresolved 0.190
```

Both exit 0. FinalSay is the only system with a 0.000 false-confirmation rate on both splits — the baselines (`chronological`, `nli`, `prompted_llm`) wrongly confirm at 0.143–0.429 — because confidence gating sends ambiguous pairs to the reviewer queue instead of asserting `consistent`. The harness docstring and printed report both carry the "naturalistic phrasing / not guaranteed perfect" note, so the numbers won't be mistaken for round-trip plumbing.

### Submit gating and the removed fixture seam

`POST /api/ingest/submit` now depends on `require_role("student", "admin")` rather than `get_current_user`, keeping the per-actor route model consistent while retaining admin as an operational override.

`MockComparisonModel` no longer has a `fixtures` constructor arg — no `fixtures=` construction exists anywhere in the backend, and both `get_comparison_model()` and the harness build a bare `MockComparisonModel()`. The docstring now states classification is 100% rule-based, matching the running behavior.

### Alerts stub labeled

`AlertsPage.tsx` renders a "Prototype stub" paragraph stating subscriptions live in localStorage only, don't sync across devices, and have no server-side push/email delivery, while the feed remains real `/api/notices` data. The client-only nature is now disclosed rather than presented as durable state.
