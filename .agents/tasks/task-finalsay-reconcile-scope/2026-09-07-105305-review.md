# Scope-note reconciliation: 308-pair benchmark, sixth eval metric, stated retention policy (v1)

This pass reconciles the FinalSay prototype against the authoritative FinalSay-Scope-Note-v2 across three deltas: the labelled benchmark grows from 14 hardcoded triples to 308 deterministically generated double-annotated pairs (Cohen's kappa 0.625), the eval harness gains the sixth required metric (time-to-identify-applicable-notice) reported for FinalSay and all four baselines on both splits, and an explicit retention-and-redaction policy is written into requirements.md/design.md/README.md and backed by a behavioral persistence test. The benchmark scaling is a self-contained data change — the held-out eval fixtures were not touched — and the retention behavior already existed structurally, so this pass mostly adds the missing *stated* policy plus a test with real teeth. All 57 backend tests pass, seed is idempotent (308 pairs / 616 annotations across two runs), and both eval splits exit 0.

Watch for: (1) the time-to-identify proxy hardcodes FinalSay's scan cost to a constant 1.0 rather than deriving it from actual `retrieve_candidates` rank, so the `finalsay <= chronological` test is true by construction and does not validate that retrieval actually surfaces the applicable official (likely). (2) The retention "raw fetched files kept only for the duration of evaluation / not retained beyond it" clause (R2.7) is a policy statement with no enforcing code — no deletion path exists (confirmed); acceptable since the scope point asks for a stated policy, but the docs imply an active guarantee.

**Verdict**: APPROVED

## High-level view

The benchmark is now a first-class labelled dataset decoupled from the ~65 eval gold submissions. `generate_benchmark_triples()` cycles all seven relationship labels (44 each = 308) and injects deterministic, independent annotator disagreement confined to genuinely confusable label pairs, landing kappa at a realistic 0.625 rather than an effective 1.0. Idempotency is preserved by pairing triple `i` with `submission[i % 65]` and `official[i % 120]` — distinct combinations for all 308 rows since the pairing cycle length (1560) far exceeds 308.

The sixth metric models "time-to-identify" as a reverse-chronological scan-cost proxy: how many notices a student reads before reaching the applicable official. Chronological-style baselines pay the official's recency rank; FinalSay is assigned a constant 1.0. The proxy is documented honestly as a proxy with no wall-clock claim, but the FinalSay=1.0 value is an idealized assumption of perfect retrieval, not a measured retrieval rank — the harness never calls `retrieve_candidates` for this metric.

The retention policy is stated in all three docs covering all four scope points, and the redaction-before-storage guarantee is verified (not merely asserted) by a test that persists PII, re-reads from the DB, and checks masks are present and originals absent across `redacted_text`, every persisted string attribute, and every stored field. The test genuinely fails when redaction is disabled.

Held-out honesty is intact: the tracked `seed/fixtures/*.json` are unchanged in the diff and remain byte-stable after a seed run, and temporal-split FinalSay relationship F1 stays ~0.05 (not a round-trip 1.0) with a 0.000 false-confirmation rate.

### Benchmark generation: deterministic disagreement on confusable pairs

`generate_benchmark_triples()` cycles gold through all seven labels and flips each annotator to the single most-confusable label on a fixed schedule — annotator A on `i % 7 == 3`, annotator B on `i % 4 == 0`. The confusion map is restricted to genuine taxonomy ambiguities (superseded↔contradictory, extended↔superseded, corrected↔consistent, unresolved↔contradictory), so the disagreement reads like annotator noise rather than uniform corruption. Over the 308 triples, A disagrees with gold 44 times, B 77 times, and the two annotators disagree with each other on 99 pairs, yielding kappa 0.625 — strictly between 0 and 1. Gold is perfectly balanced (44 per label including `unresolved`), and all 44 unresolved pairs persist as `BenchmarkPair` rows: the old code filtered `!= "unresolved"` out of benchmark pairing, and the rewrite drops that filter, so unresolved gold is now represented.

The benchmark is entirely synthetic and structurally regular — every "consistent"-gold triple at the same `i mod 28` is identical — so it is a kappa fixture, not human annotation. The docstrings and HANDOFF describe it as deterministic generation rather than claiming real annotators, which keeps the characterization honest.

### Idempotency of the scaled seed

`_seed_benchmark` no longer bounds the benchmark to the count of gold submissions. It pairs triple `i` with `submission[i % 65]` / `official[i % 120]`, guarding on the `(submission_id, official_id)` natural key. The uniqueness argument holds independent of gcd: the pair `(i mod 65, i mod 120)` repeats only after `lcm(65, 120) = 1560` steps, and 308 < 1560, so every row is a distinct combination and a second run finds all pairs present. Verified: two consecutive seed runs both report `benchmark_pairs=308, benchmark_annotations=616` with every other table stable.

### Time-to-identify proxy and the constant FinalSay cost

`_chronological_rank()` derives the applicable official's 1-based position in its institution's newest-first feed (institution from the `external_id` prefix, dates parsed from `gold_date`, ties broken by external_id for determinism), DB-free. Chronological, page_change, nli, and prompted_llm all inherit that rank; FinalSay is assigned `1.0` for every held-out pair. The module docstring and printed report both flag this as a proxy with no live-user timing.

FinalSay's `1.0` is a modeling assumption, not a measurement. `_predict_finalsay` takes the applicable official directly from the gold pairing and never calls `services.comparison.retrieve_candidates`, which ranks officials by lexical overlap and truncates to `top_k` — real retrieval can rank the applicable official below 1 or miss it entirely. So the `time_to_identify` value for FinalSay cannot fall below 1.0 regardless of retrieval quality, and `test_time_to_identify_finalsay_at_most_chronological_both_splits` is satisfied by the constant, not by any property of FinalSay's retrieval. The reported 19.29x / 17.86x speedups are best-case figures assuming perfect retrieval recall at rank 1. This does not weaken any prior guarantee, but the docstring's "surfaces the applicable official directly ... so its scan cost is 1" reads as a measured fact rather than the idealization it is.

### Retention policy: stated in three docs, verified in code

All four scope points appear in each of requirements.md (EARS reqs R2.5–R2.8), design.md (section 5 retention note), and README.md (Data handling and retention): identifiers redacted before storage/indexing, unredacted original not retained, raw files kept only for evaluation duration, released benchmark redacted-only. The unredacted-original guarantee is structural — the `Notice` table has `redacted_text` and no pre-redaction column — and `test_persisted_submission_holds_only_redacted_text_no_unredacted_original` proves it behaviorally: it persists PII-laden text via `create_submission`, commits, `expunge_all()`, re-reads, and asserts masks present and all five original PII strings absent from `redacted_text`, every persisted string attribute, and every `NoticeField` value, plus that no unredacted-named column exists. Disabling `redact()` in-process makes all five PII strings leak into `redacted_text` and the test fails, confirming it is not a tautology. A second test covers the official upsert path.

R2.7's "raw fetched files kept only for the duration of the project evaluation and not retained beyond it" is the one clause with no code behind it — there is no deletion or expiry path in the ingestion or provenance services. For a scope point that asks for a *stated* policy this is acceptable, but the SHALL-phrasing in requirements.md and the README's active-voice wording imply a runtime guarantee the code does not enforce.

### Held-out honesty and bundled changes

The tracked eval fixtures (`seed/fixtures/gold_submissions.json` and the three institution files) show no changes in `git diff 4b0deeb` and remain byte-identical after a seed run, so `write_fixtures()` is deterministic and the temporal-holdout naturalistic phrasings were not contaminated by the benchmark scaling. Temporal-split FinalSay relationship F1 stays ~0.05 with a 0.000 false-confirmation rate — no sign of the benchmark leaking into eval scoring. The diff is scoped to the three features plus HANDOFF.md; no unrelated changes are bundled in.
