# FinalSay evaluation results

Auto-generated by the evaluation harness (`python -m finalsay.eval.harness ... --report docs/eval-results.md`).
This file is report-ready: it carries the full **six metrics × five systems × both splits** for both comparison models. Numbers are recorded **exactly as measured** — per the project integrity constraint, nothing is inflated, tuned, or cherry-picked; a worse honest number is reported as-is.

## Two comparison models

- **MOCK** (`FINALSAY_COMPARISON_MODEL` unset / `mock`) is the **default, zero-setup** path: a deterministic, offline rule engine. It needs no extra dependencies and powers the no-paid-keys demo. This is the default and it is **not** changed by the HF run below.
- **HF** (`FINALSAY_COMPARISON_MODEL=hf`) is **opt-in**: zero-shot NLI with `facebook/bart-large-mnli` via `transformers`/`torch`. The model weights (~1.6 GB) download on first run and it runs CPU-only here.

## HF run: environment and runtime (measured)

The HF blocks below were produced by executing the real `facebook/bart-large-mnli` zero-shot path **once** per split on this sandbox (CPU-only, `torch==2.14.0+cpu`, `transformers==5.16.1`, Python 3.11):

- **Temporal split** (21 held-out pairs): **~33 s** wall-clock end to end. The ~1.6 GB weights were fetched to the local HF cache before this run (a cold first-ever download adds a few minutes, network-dependent).
- **Institution split** (21 held-out pairs): **~28 s** wall-clock (weights already cached).

The HF model only affects the **`finalsay`** system's relationship classification. Per-field extraction F1, Cohen's kappa, the four baselines, and the whole time-to-identify metric are model-independent, so those numbers are identical across the MOCK and HF blocks (as expected — only the ComparisonModel changed).

**Honest MOCK-vs-HF comparison (finalsay relationship F1 on the held-out splits):** on the `temporal` split HF scores **0.143** vs MOCK **0.048**; on the `institution` split HF scores **0.289** vs MOCK **0.739**. So swapping in the real NLI model makes FinalSay **worse** on the institution split (and it also trails the `nli`/`prompted_llm` baselines there), while nudging the temporal split up from a very low base. Both models keep FinalSay's **false-confirmation rate at 0.000** (HF routes far more cases to `unresolved`: 0.714 vs MOCK's 0.286/0.190). These numbers are reported exactly as measured; nothing was tuned to make either model look better.

## Reproduce

MOCK (default, no setup):

```bash
cd backend
.venv/bin/python -m finalsay.eval.harness --split temporal --report docs/eval-results.md
.venv/bin/python -m finalsay.eval.harness --split institution --report docs/eval-results.md
# or regenerate every block (both splits × both models) in one shot:
.venv/bin/python -m finalsay.eval.harness --report-all docs/eval-results.md
```

HF (opt-in; installs the heavy stack into the venv only — NOT into `requirements.txt`):

```bash
cd backend
# optional recorded manifest: backend/requirements-hf.txt
.venv/bin/pip install -r requirements-hf.txt   # transformers + CPU torch
# keep the model cache under the repo so it persists:
export HF_HOME=/projects/sandbox/.hf-cache
FINALSAY_COMPARISON_MODEL=hf .venv/bin/python -m finalsay.eval.harness \
    --split temporal --model hf --report docs/eval-results.md
FINALSAY_COMPARISON_MODEL=hf .venv/bin/python -m finalsay.eval.harness \
    --split institution --model hf --report docs/eval-results.md
```
